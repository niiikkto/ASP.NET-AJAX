# Конспект: Управление HTTP-запросами в JavaScript и React (`fetch` & `AbortController`)

> *Примечание: несмотря на случайные директивы `using` из C# в начале исходного файла, весь приведенный код написан на **JavaScript / React**.*

Документ систематизирует подходы к отмене запросов, обработке таймаутов, предотвращению состояний гонки (*Race Conditions*) и проектированию надежных оберток над `fetch`.

---

## 1. Жизненный цикл и состояния запроса

Любой асинхронный запрос в UI можно описать конечным автоматом из 5 состояний:

| Состояние | Описание |
| :--- | :--- |
| **`idle`** | Начальное состояние: запрос ещё не отправлялся. |
| **`loading`** | Запрос выполняется в данный момент. |
| **`success`** | Запрос завершен успешно, получены данные. |
| **`error`** | Произошла реальная ошибка (сеть или HTTP-статус `4xx`/`5xx`). |
| **`aborted`** | Запрос отменен вручную через `AbortController` (не считается ошибкой для UI). |

---

## 2. Основы `AbortController` и особенности `fetch`

### Базовый принцип отмены
1. Создается экземпляр `const controller = new AbortController()`.
2. В `fetch(url, { signal: controller.signal })` передается объект `signal`.
3. Вызов `controller.abort()` прерывает запрос и отклоняет промис с ошибкой `error.name === 'AbortError'`.

### Важные нюансы `fetch`
* **HTTP-ошибки не выбрасывают исключение:** Для статусов `404` или `500` промис `fetch` успешно разрешается (*resolves*). Необходимо вручную проверять флаг `if (!response.ok) throw new Error(...)`.
* **Фильтрация отмены:** В блоке `catch` нужно отделять намеренную отмену (`error.name === 'AbortError'`) от сетевых сбоев и ошибок сервера, чтобы не показывать пользователю ложные уведомления об ошибках.

## 3. Таймауты и комбинирование сигналов

Современный стандарт предлагает встроенные статические методы для `AbortSignal` (без ручного создания `setTimeout`):

1. **Автоматический таймаут (`AbortSignal.timeout(ms)`):**
   * Прерывает запрос по истечении заданного времени.
   * Выбрасывает `DOMException` с именем **`TimeoutError`**.
2. **Объединение сигналов (`AbortSignal.any([...])`):**
   * Позволяет передать в `fetch` сразу несколько условий отмены (например, ручную отмену пользователем + ограничение по времени). Сработает тот сигнал, который наступит раньше.

```javascript
const combinedSignal = AbortSignal.any([userSignal, AbortSignal.timeout(8000)]);
fetch(url, { signal: combinedSignal });
```

## 4. Состояние гонки (*Race Condition*) и способы борьбы

**Проблема:** При быстром вводе текста в поиск или быстрых кликах по вкладкам ответы от сервера могут прийти не в том порядке, в котором отправлялись запросы. Более медленный старый запрос перезапишет актуальные данные.

### Эволюция решений

1. **Только отмена (`AbortController`):**
   * Перед запуском нового запроса вызывается `activeController.abort()`.
   * *Плюс:* экономит трафик и ресурсы браузера/сервера.
   * *Минус:* если ответ уже скачался и идет этап парсинга (`response.json()`), отмена может не успеть остановить рендер.
2. **Только счетчик запросов (Sequence ID):**
   * Каждому запросу присваивается инкрементный номер `const myId = ++requestId`.
   * После `await` проверяется `if (myId !== requestId) return;` (игнорируются как данные, так и ошибки устаревших запросов).
   * *Плюс:* стопроцентная защита от устаревшего рендера.
   * *Минус:* ненужные запросы продолжают висеть в сети.
3. **Комбинированный подход («Отмена + Счетчик») — эталон:**
   * `AbortController` обрывает сетевое соединение.
   * Счетчик `myId` страхует на этапе парсинга JSON и управляет снятием индикатора загрузки (`finally { if (myId === currentRequestId) onLoading(false); }`).
4. **Паттерн «Последний запрос побеждает» (`createLatestOnly`):**
   * Инкапсуляция логики *«Отмена + Счетчик»* в переиспользуемую функцию-обертку высшего порядка.

## 5. Практические паттерны в UI и React

### Хук `useFetch` на базе `useReducer`
* **Единый `useReducer`:** Исключает невозможные комбинации состояний (например, когда одновременно `loading: true` и `error !== null`).
* **Хранение контроллера в `useRef`:** Позволяет сохранять ссылку на активный `AbortController` между ре-рендерами компонента.
* **Функция очистки (Cleanup) в `useEffect`:** Возврат `() => controller.abort()` автоматически отменяет запрос при размонтировании компонента или смене `url`, предотвращая утечки памяти и попытки обновить состояние размонтированного компонента.

### Защита формы от двойного клика
* Используется комбинация флага блокировки `isSubmitting` (для мгновенного игнорирования повторных кликов и отключения кнопки `button.disabled = true`) и `AbortController`.

### Поиск с `Debounce` + `AbortController`
* **`debounce(fn, 300)`** откладывает отправку запроса, пока пользователь печатает.
* **`AbortController`** отменяет уже ушедший запрос, если пользователь сделал паузу, а затем продолжил ввод.

## 6. Универсальная обертка `safeFetch`

Инкапсулирует рутинные проверки в единую функцию:
* Объединяет пользовательский `signal` и таймаут через `AbortSignal.any`.
* Автоматически парсит JSON или текст в зависимости от заголовка `Content-Type`.
* При статусах `!response.ok` извлекает детали ошибки из JSON-тела ответа (`body?.message`).
* Различает причины `AbortError`: если сработал `timeoutSignal`, выбрасывает ошибку таймаута; если отменил пользователь — возвращает безопасный объект `{ aborted: true }` без выброса исключения.
* Перехватывает сетевые сбои (`TypeError`) и преобразует их в понятное сообщение об отсутствии сети.
